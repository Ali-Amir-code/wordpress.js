# Product vision

## Who and why

Start with small business owners and independent bloggers who need to launch and maintain a good website without hiring a developer for routine edits. Developers should be able to extend and self-host the product without buying a platform subscription. MIT licensing and this initial audience were selected by the project owner.

The product should combine the approachable publishing workflow of classic WordPress with typed JavaScript components, portable content and a visual editor. It is an independent implementation, not a PHP emulator or a promise of WordPress plugin/theme compatibility.

## Core journeys

1. Install locally, create an owner account, and name a site.
2. Choose a starting layout, edit text and blocks, preview on different screen sizes.
3. Save work privately, then deliberately publish it at a stable address.
4. Publish blog posts and keep pages up to date without taking the public site offline.
5. Grow into media management, navigation, themes, forms and multiple editors.

## Design principles

- A calm workspace: clear content lists, visible publication state, predictable navigation.
- Safe publication: editing a published page must not change the live version until republished.
- Useful defaults: accessible components, mobile layouts, descriptive metadata and server-rendered pages.
- Ownership: no account with a third-party service required, no telemetry by default, exportable structured content.
- Honest interfaces: no fake analytics, nonfunctional marketplace, or unsupported feature switches.
- Progressive complexity: common tasks come first; developers get explicit contracts and extension points.

## Product scope

The complete vision includes pages, posts, reusable patterns, theme tokens, menus, media, forms, SEO, search, redirects, roles, revision history, scheduling, localization, backups, APIs, plugins and deployment tools. Commerce, memberships and real-time collaboration come after the publishing platform is stable.

Success criteria for the first milestone: a new contributor can start the app using the README, create a site, edit a starter page, publish it, verify public HTML, and change the draft without changing the published version. No marketing claims about scale, accessibility conformance or production readiness are made before measurement.
